## 2026-11-07 - [CSV Injection Vulnerability in Trading Monitor]
**Vulnerability:** The trade logging functionality in `monitor.py` was directly writing unsanitized trade data to a CSV file (`trades.csv`). If a malicious user could control fields like `symbol` or `comment` and input data starting with `=`,`+`,`-`, or `@`, they could perform CSV Injection (also known as Formula Injection) when the CSV is opened in spreadsheet software like Excel.
**Learning:** Even when logging data locally, user-controlled input or external data (like trade comments or symbols) must be sanitized before being written to CSV files to prevent execution of malicious commands or data exfiltration upon viewing the file. Pure numeric fields should be left alone so data types are preserved and downstream systems don't fail, but string fields starting with formula characters must be prepended with a single quote `'`.
**Prevention:** Always sanitize input going into CSV generation functions. A robust sanitization function checks if the input is a string, leaves pure floats/integers untouched, strips leading whitespace, and escapes problematic leading characters (`=`, `+`, `-`, `@`) with a single quote. This function should be applied consistently to all rows written to a CSV.
