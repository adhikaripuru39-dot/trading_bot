## 2026-10-09 - CSV Injection Vulnerability in Trade Logs
**Vulnerability:** The `Monitor` class's `log_trade` method writes user-controllable input (like `symbol` and `comment`) directly to a CSV file (`trades.csv`) without sanitization. If an attacker can control these fields (e.g., via MT5 comment fields or unexpected symbol names), they could inject malicious formulas (starting with `=`, `+`, `-`, or `@`). When opened in spreadsheet software like Excel, this can lead to Remote Code Execution (RCE) via DDE injection or data exfiltration.
**Learning:** Even internal logging mechanisms like CSV trade logs are susceptible to injection attacks if the data being logged originates from untrusted sources or systems where user input is reflected. It's crucial to differentiate between purely numeric values (like negative PnL or prices) and potentially malicious strings starting with formula characters to avoid corrupting legitimate data while mitigating the risk.
**Prevention:** Sanitize all string fields written to CSVs by prepending a single quote (`'`) to any string that begins with a known formula trigger character (`=`, `+`, `-`, `@`), while explicitly skipping strings that are purely numeric (e.g., negative numbers like `-150.50`).
