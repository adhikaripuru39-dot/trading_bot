## 2026-10-07 - [CSV Injection Vulnerability in Monitor Logs]
**Vulnerability:** The trading bot's `Monitor` class logged trade details to a CSV file (`trades.csv`) using the Python `csv` module without sanitizing input fields (such as trade comments or other string fields). This exposed the application to CSV Injection vulnerabilities where an attacker could construct malicious input starting with `=`, `+`, `-`, or `@` that, when opened in spreadsheet software like Excel, could execute arbitrary commands or leak data.
**Learning:** It is crucial to sanitize string inputs before writing them to CSV logs, even if they are generated internally, as parts of the input (like user comments or symbol names pulled from external sources) could be attacker-controlled. The `csv` module does not prevent this automatically. Care must also be taken to NOT sanitize purely numeric strings (e.g., `-150.50`) as prefixing them with a single quote can corrupt numeric data when the CSV is parsed back by pandas or other downstream tools.
**Prevention:** Implement an input sanitization function that prepends a single quote (`'`) to string fields beginning with `=`, `+`, `-`, or `@`. Ensure purely numeric fields are safely passed through without sanitization by verifying they can be cast to `float`. Apply this sanitization to all fields before writing to CSVs using the `csv` module.
